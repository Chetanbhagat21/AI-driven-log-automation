### **Issue Title:** 
`Race Condition: Concurrent checkout requests leading to negative inventory levels`

### **Issue Description:**
Users are able to purchase items even when the stock is at zero. When multiple requests are sent simultaneously for the same product, the `inventory` count in the database is being decremented incorrectly, resulting in negative values (e.g., stock: -3). This suggests that the current implementation of `updateInventory` does not handle concurrent transactions safely.

---

### **1. Root Cause**
The issue is a classic **"Read-Modify-Write" race condition**. 

The current implementation performs the following steps:
1. Fetches the current stock level from the database (`SELECT`).
2. Validates in the application logic if `stock > quantity`.
3. Calculates the new stock and saves it back to the database (`UPDATE`).

When two requests arrive at the same time, both read the same initial stock value (e.g., 1). Both pass the validation check, and both attempt to decrement the value. The second update overwrites the first, or both succeed in sequence, resulting in a stock of -1. The application fails to use **Atomic Updates** or **Database Locking (Pessimistic/Optimistic)** to ensure data integrity during high concurrency.

---

### **2. Fixed Code**

We will shift from application-level calculation to **Atomic Database Updates** using a single query with a `WHERE` clause constraint.

#### **Before (Buggy):**
```javascript
async function updateInventory(productId, quantity) {
  const product = await db.Product.findById(productId);
  
  if (product.stock < quantity) {
    throw new Error('Insufficient stock');
  }

  const newStock = product.stock - quantity;
  return await db.Product.update({ id: productId }, { stock: newStock });
}
```

#### **After (Fixed - Using Atomic Update):**
```javascript
/**
 * Updates inventory safely using an atomic operation.
 * Ensures stock never drops below zero by leveraging DB-level constraints.
 */
async function updateInventory(productId, quantity) {
  // Use a single query to decrement stock only if sufficient balance exists.
  // This is an atomic operation at the DB level.
  const [affectedRows] = await db.Product.update(
    {
      stock: db.sequelize.literal(`stock - ${quantity}`)
    },
    {
      where: {
        id: productId,
        stock: {
          [db.Sequelize.Op.gte]: quantity // Ensure stock is >= requested quantity
        }
      }
    }
  );

  if (affectedRows === 0) {
    // If no rows were updated, it means either product doesn't exist 
    // or the stock constraint (stock >= quantity) failed.
    const product = await db.Product.findById(productId);
    if (!product) throw new Error('Product not found');
    throw new Error('Insufficient stock for concurrent transaction');
  }

  return { success: true };
}
```

---

### **3. Explanation**

1.  **Atomic Operations**: Instead of pulling the value into Node.js memory, we delegate the calculation to the Database Engine (`SET stock = stock - quantity`). SQL databases handle concurrent updates to the same row by queuing them, ensuring each operation is executed based on the most recent state.
2.  **Conditional Update**: By adding `WHERE stock >= quantity` to the update statement, we ensure that even if the database processes two requests sequentially, the second request will fail the `WHERE` condition because the first request already reduced the stock.
3.  **Performance**: This approach removes the need for a separate `SELECT` query, reducing database round-trips and minimizing the overhead of heavy Row Locking (Pessimistic Locking), which improves API throughput.
4.  **Row Count Validation**: We check `affectedRows`. If it's `0`, the update didn't happen, which we treat as a "Concurrency Failure" or "Out of Stock" error.
