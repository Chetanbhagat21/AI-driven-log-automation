### **Issue Title:** 
`UnhandledPromiseRejectionWarning` in `authMiddleware` causing request hangs during DB downtime.

### **Issue Description:**
When the database is unreachable or times out, the `verifyToken` function inside `authMiddleware` throws an error. Because the middleware is `async` and lacks a proper catch block, Express 4.x does not catch the error. This results in:
1. The client receiving no response (request hangs until timeout).
2. `UnhandledPromiseRejectionWarning` logged to the console.
3. Potential process termination in Node.js 15+ environments.

---

### **1. Root Cause**
The `authMiddleware` is defined as an `async` function. In Express.js version 4.x, the internal routing logic is wrapped in a `try-catch` that only handles synchronous errors. 

When an `await`ed promise rejects (e.g., `db.users.find()`), the exception is not caught by the framework. Since the code does not explicitly call `next(err)`, the error skips the Express error-handling pipeline. This leaves the request-response cycle open and generates an unhandled rejection at the Node.js process level.

---

### **2. Fixed Code**

#### **Option A: The Utility Wrapper (Recommended for Scalability)**
Instead of adding `try-catch` to every route, we implement a higher-order function to ensure all async errors are passed to `next()`.

**`utils/catchAsync.js`**
```javascript
/**
 * Wraps an asynchronous function and forwards any caught errors to the 
 * next middleware in the stack.
 */
const catchAsync = (fn) => {
  return (req, res, next) => {
    fn(req, res, next).catch(next);
  };
};

module.exports = catchAsync;
```

**`middleware/authMiddleware.js` (Fixed)**
```javascript
const User = require('../models/User');
const catchAsync = require('../utils/catchAsync');
const AppError = require('../utils/AppError');

const protect = catchAsync(async (req, res, next) => {
  let token;
```

### **3. Explanation**
*   **The Wrapper Mechanism:** The `catchAsync` function accepts the middleware logic as an argument. It returns a new function that calls the original logic but attaches a `.catch(next)` to the returned Promise.
*   **Express Error Pipeline:** By calling `next(err)`, we explicitly tell Express to skip all remaining non-error middlewares and jump directly to the global error-handling middleware (usually defined as `app.use((err, req, res, next) => ...)`).
*   **Process Stability:** This approach converts unhandled rejections into standard HTTP 500 (or custom) responses, preventing the Node.js process from entering an unstable state or crashing.
*   **Cleanliness:** We avoid "Try-Catch Hell" by centralizing error bubbling, making the business logic more readable.
