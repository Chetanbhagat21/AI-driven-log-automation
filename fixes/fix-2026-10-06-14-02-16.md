### Assumed Issue Details
**Issue Title:** `[CRITICAL] Unhandled Promise Rejection in Express async handler during batch processing crashes Node.js server`  
**Issue Description:** Under high load or when database timeouts occur, the endpoint `POST /api/v1/users/batch-update` crashes the Node.js process with `ERR_UNHANDLED_REJECTION`. The endpoint uses `Promise.all()` over an `async` `.map()` array transformation without localized error catching or proper Express error propagation.

---

### 1. Root Cause

1. **Express 4 Async Error Handling Limitation:** Express 4.x does not automatically catch rejected promises returned from `async` middleware/route handlers. When an error is thrown inside an unhandled `async` route function, it is not passed to Express's `next(err)` middleware.
2. **`Promise.all` Fail-Fast Rejection Leak:** In `Promise.all(items.map(async item => ...))`, if one promise rejects, `Promise.all` immediately rejects. However, the remaining concurrent async mapping promises continue executing in the background. When those remaining promises subsequently fail, their rejections are no longer being listened to by `Promise.all`, resulting in **Unhandled Promise Rejections**.
3. **Node.js v15+ Process Termination:** As of Node.js v15+, the default `unhandledRejection` mode is set to `throw`, causing unhandled promise rejections to crash the entire Node.js runtime process (`ERR_UNHANDLED_REJECTION`).
4. **Database Connection Leak:** Database connections/transactions opened inside the `.map()` execution loop lack a `finally` block, causing connection pool exhaustion when an unhandled exception breaks execution mid-flight.

```javascript
// src/controllers/userController.js
const userService = require('../services/userService');
const ApiError = require('../utils/ApiError');

/**
 * Handles batch updating of users safely without unhandled rejections or resource leaks.
 */
exports.batchUpdateUsers = async (req, res, next) => {
  try {
    const { users } = req.body;

    if (!Array.isArray(users) || users.length === 0) {
      throw new ApiError(400, 'Payload must contain a non-empty array of users.');
    }

    // Use Promise.allSettled to guarantee every promise resolves or rejects gracefully
    const settlementResults = await Promise.allSettled(
      users.map((user) => userService.updateUserInDb(user))
    );

    const succeeded = [];
    const failed = [];

    settlementResults.forEach((result, index) => {
      if (result.status === 'fulfilled') {
        succeeded.push(result.value);
      } else {
        failed.push({
          userId: users[index].id || null,
          reason: result.reason.message || 'Unknown processing error',
        });
      }
    });

    return res.status(200).json({
      success: true,
      meta: {
        total: users.length,
        succeededCount: succeeded.length,
        failedCount: failed.length,
      },
      data: {
        succeeded,
        failed,
      },
    });
  } catch (error) {
    // Safely forward error to Express global error handling middleware
    return next(error);
  }
};
```

```javascript
// src/services/userService.js
const db = require('../config/database');

/**
 * Updates a single user with explicit resource cleanup.
 */
exports.updateUserInDb = async (userData) => {
  const client = await db.getClient();
  try {
    await client.query('BEGIN');
    
    const query = 'UPDATE users SET name = $1, updated_at = NOW() WHERE id = $2 RETURNING *';
    const response = await client.query(query, [userData.name, userData.id]);
    
    if (response.rowCount === 0) {
      throw new Error(`User with ID ${userData.id} not found.`);
    }

    await client.query('COMMIT');
    return response.rows[0];
  } catch (error) {
    await client.query('ROLLBACK');
    throw error; // Re-throw to be caught by Promise.allSettled
  } finally {
    client.release(); // Ensures connection is always returned to pool
  }
};
```

### 3. Explanation

1. **`Promise.allSettled` vs `Promise.all`:**  
   Replaced `Promise.all` with `Promise.allSettled`. Unlike `Promise.all` (which rejects instantly on the first error), `Promise.allSettled` waits for all operations to finish regardless of success or failure. This guarantees that no late-rejecting background promises become unhandled rejections.

2. **Express Error Middleware Propagation (`try / catch / next`):**  
   Wrapped the top-level route controller in a `try...catch` block that passes synchronous or asynchronous errors to `next(error)`. This delegates unexpected server errors to Express's centralized error-handling middleware rather than crashing the process.

3. **Guaranteed Connection Pool Cleanup (`finally` block):**  
   Added a `finally` block in `updateUserInDb` to invoke `client.release()`. This ensures database connections are returned to the connection pool even if an error occurs, preventing connection leaks during DB outages or timeouts.

4. **Partial Failure Resilience:**  
   The endpoint response now categorizes batch items into `succeeded` and `failed` arrays, allowing clients to identify which records succeeded and which failed without failing the entire batch request.
