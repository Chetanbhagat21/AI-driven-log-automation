### **Example Scenario (For Demo Purposes)**
**Issue Title:** `Duplicate Key Error on User Registration under high concurrency`
**Issue Description:** `When multiple requests are sent simultaneously with the same email, the unique constraint in MongoDB is violated, but the application doesn't catch it properly, leading to a 500 Internal Server Error instead of a 400 Bad Request.`

---

### 1. Root Cause
The application performs a "check-then-insert" logic (`findUserByEmail` followed by `createUser`) without an atomic transaction or proper error handling for the database's unique constraint violation. Under high concurrency, two requests pass the `findUserByEmail` check simultaneously. The first one inserts the record successfully, while the second one fails at the database level with a `11000` MongoServerError (Duplicate Key), which is not caught by the controller, causing the process to throw an unhandled exception or return a generic 500 error.

### 2. Fixed Code

```javascript
// services/user.service.js
const User = require('../models/user.model');
const { ConflictError } = require('../utils/errors');

/**
 * Creates a new user with duplicate key handling
 * @param {Object} userData 
 */
exports.registerUser = async (userData) => {
  try {
    const newUser = new User(userData);
    return await newUser.save();
  } catch (error) {
    // Check for MongoDB Duplicate Key Error (code 11000)
    if (error.code === 11000) {
      throw new ConflictError('Email address already exists.');
    }
    // Re-throw other unexpected errors
    throw error;
  }
};

// controllers/user.controller.js
exports.signup = async (req, res, next) => {
  try {
    const user = await userService.registerUser(req.body);
    res.status(201).json({ success: true, data: user });
  } catch (error) {
    // Pass to global error handler
    next(error);
  }
};
```

### 3. Explanation
*   **Atomic Reliability:** Instead of relying on a pre-save check (which is susceptible to race conditions), we rely on the database's unique index as the "source of truth."
*   **Error Mapping:** We specifically catch the database driver's error code (`11000`) and map it to a meaningful `ConflictError` (HTTP 409).
*   **Global Error Handling:** By passing the error to `next(error)`, we ensure the Node.js process doesn't crash and that the client receives a structured JSON response instead of a generic HTML error page.
*   **Performance:** Removing the initial `findOne` query reduces database round-trips by 50% for successful registrations.
