### Issue Title:
`FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed - JavaScript heap out of memory` in `ReportGenerationService`

### Issue Description:
The backend service crashes every 48 hours in production. Heap dumps indicate an accumulation of `EventEmitter` listeners in the `ReportGenerationService`. This happens specifically when users cancel PDF exports, but the underlying database stream listeners are never cleaned up.

---

### 1. Root Cause
The `ReportGenerationService` uses a custom event emitter to track progress. When a client disconnects (e.g., closes the browser or cancels the request), the `http.IncomingMessage` "close" event is triggered. 

However, the code was attaching listeners to the `reportStream` inside the request lifecycle but failing to remove them if the stream was interrupted early. In Node.js, `EventEmitter` references stay in memory as long as the listener is attached, preventing the Garbage Collector (GC) from reclaiming the `reportStream` and associated buffer objects.

### 2. Fixed Code

```javascript
// services/ReportGenerationService.js

const { EventEmitter } = require('events');

class ReportGenerationService {
  async generateLargeReport(res, userId) {
    const reportStream = await this.db.streamData(userId);
    const cleanup = () => {
      // Senior approach: Ensure all listeners are detached to prevent leaks
      reportStream.removeAllListeners('data');
      reportStream.removeAllListeners('error');
      reportStream.removeAllListeners('end');
      if (!reportStream.destroyed) {
        reportStream.destroy();
      }
    };

    // Handle client disconnection
    res.on('close', () => {
      console.log(`Client disconnected. Cleaning up resources for user: ${userId}`);
      cleanup();
    });

    return new Promise((resolve, reject) => {
      reportStream.on('data', (chunk) => {
        const canContinue = res.write(chunk);
        if (!canContinue) {
          reportStream.pause();
          res.once('drain', () => reportStream.resume());
        }
      });

      reportStream.on('error', (err) => {
        cleanup();
        reject(err);
      });

      reportStream.on('end', () => {
        res.end();
        cleanup();
        resolve();
      });
    });
  }
}
```

### 3. Explanation
*   **Listener Lifecycle Management:** In the original code, if a user canceled a request, the stream remained in a "paused" or "waiting" state with active listeners. By implementing a `cleanup()` function triggered by `res.on('close')`, we ensure that the stream is explicitly destroyed and listeners are removed.
*   **Backpressure Handling:** I added logic to check the return value of `res.write(chunk)`. If the internal buffer is full, we pause the database stream and wait for the `drain` event. This prevents the Node.js process from buffering massive amounts of data in RAM, further protecting against OOM (Out of Memory) errors.
*   **Explicit Destruction:** Calling `reportStream.destroy()` is crucial for closing underlying database cursors/sockets immediately rather than waiting for the GC.
