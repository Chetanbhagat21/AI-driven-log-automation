### Issue Title: `FATAL ERROR: Ineffective mark-compacts near heap limit Allocation failed - JavaScript heap out of memory` during CSV Export

### Issue Description:
When users attempt to export reports containing more than 50,000 records, the backend worker process crashes. Monitoring shows memory usage climbing linearly until the OOM (Out of Memory) killer terminates the process. This prevents large reports from ever completing.

---

### 1. Root Cause
The current implementation fetches the entire dataset from the database into an array in memory (`await model.find().toArray()`). 

1. **Heap Exhaustion:** Loading 50k+ complex JSON objects into the V8 heap exceeds the default memory limit (usually 2GB in many environments).
2. **Buffer Overhead:** Stringifying a massive array into a single CSV string creates a second, massive allocation in the buffer, doubling the memory pressure.
3. **Blocking the Event Loop:** Synchronous JSON processing of a large array blocks the event loop, causing health check failures and making the service unresponsive before it even crashes.

---

### 2. Fixed Code

**Before (Vulnerable Code):**
```javascript
// controller.js
async function exportData(req, res) {
  const data = await UserReport.find({ status: 'active' }).toArray(); // <--- Root Cause
  let csv = 'ID,Name,Email\n';
  data.forEach(row => {
    csv += `${row.id},${row.name},${row.email}\n`;
  });
  res.attachment('report.csv').send(csv);
}
```

**After (Optimized with Streams):**
```javascript
const { pipeline } = require('stream/promises');
const { Stringifier } = require('csv-stringify');

// service.js
async function exportDataStream(req, res) {
  try {
    // 1. Set headers for streaming
    res.setHeader('Content-Type', 'text/csv');
    res.setHeader('Content-Disposition', 'attachment; filename="report.csv"');

    // 2. Initialize the DB cursor (Stream-friendly)
    const cursor = UserReport.find({ status: 'active' }).cursor();

    // 3. Initialize CSV Transform Stream
    const transformer = new Stringifier({
      header: true,
      columns: ['id', 'name', 'email']
    });

    // 4. Pipeline: Source -> Transform -> Destination (Response)
    // Pipeline automatically handles backpressure and error cleanup
    await pipeline(
      cursor,
      transformer,
      res
    );

    console.log('Export completed successfully via stream.');
  } catch (err) {
    console.error('Export failed:', err);
    if (!res.headersSent) {
      res.status(500).send('Export failed');
    } else {
      res.end(); // Terminate response if headers already sent
    }
  }
}
```

---

### 3. Explanation
*   **Database Cursors:** Instead of `toArray()`, we use `.cursor()`. This fetches data from the database in small batches (default usually 1000 docs), keeping only a few records in the Node.js memory at any given time.
*   **Node.js Streams:** We utilize the `pipeline` API to connect the database source to the HTTP response destination.
*   **Backpressure Handling:** `pipeline` automatically manages "backpressure." If the network is slower than the database, the stream will signal the database cursor to pause reading until the network buffer clears, preventing memory buildup.
*   **Constant Memory Footprint:** The memory usage remains flat (e.g., ~100MB) regardless of whether we are exporting 100 rows or 1,000,000 rows.
